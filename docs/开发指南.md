# DStatus 插件开发指南

给想为自己的 DStatus 主控写插件的人（或让 AI 代写的人）。读完本文、照着样板，就能做出一个能装进主控、有后台页面、能读节点、能定时跑、能发通知、能被 AI/MCP 调用的插件。不需要改主控代码，不需要构建工具。

本文在开发者资料包里：`template/` 是可以直接复制改名的样板，`examples/` 是更完整的例子，`docs/审核标准.md` 是上架要过的检查，`docs/投稿.md` 是投稿办法，`docs/图标清单.md` 是能用的图标。

## 1. 一句话模型

一个插件 = 一个目录：`manifest.json`（清单，声明身份、权限、贡献点）+ `index.js`（后端入口，只导出 `start` / `stop`）+ 可选的 `ui/`（后台页面，纯 HTML）。开发时在自己主控的插件页打开「开发者模式」装进去自测（见第 10 节）；给别人用要经官方插件市场审核收录。

插件代码**只经 `ctx`**（宿主给的能力对象）与系统交互：读节点、存数据、存密钥、发通知、定时、出站请求、提供接口与工具。不能也不需要直接碰数据库、文件、网络；没有在清单里声明的能力，调用会被拒绝。

外部插件在主控的一个独立进程里运行（每个插件一个线程、有内存上限），插件崩了只有它自己失败，主控不受影响。

## 2. 最小插件

资料包里有两个例子：`template/`「节点备注」（各能力各用一次）和 `examples/expiry-watch`「到期提醒」（并发合并、缓存恢复、设置修订号，更接近真实插件）。先抄后者的结构不会错。

```
my-plugin/
  manifest.json
  index.js
```

`manifest.json`：

```json
{
  "format": 1,
  "type": "plugin",
  "id": "my-plugin",
  "name": "我的插件",
  "description": "每分钟数一次离线节点",
  "version": "1.0.0",
  "protocol": 2,
  "main": "index.js",
  "defaults": { "fresh": true, "upgrade": true },
  "permissions": ["nodes:read", "timers"]
}
```

`index.js`：

```js
"use strict";

async function start(ctx) {
  ctx.timers.every("count", 60 * 1000, async () => {
    const page = await ctx.nodes.list({ page: 1, limit: 100 });
    const offline = page.items.filter((n) => !n.online).length;
    ctx.log.info(`离线节点 ${offline} / ${page.total}`);
  });
}

async function stop(ctx, { reason }) {
  // 定时器由宿主清掉；这里只做自己的收尾
}

module.exports = { start, stop };
```

开发时不用打包：开发者模式里填插件目录直接装（第 10 节）。要上传 zip 时，在目录的上一级执行 `zip -r my-plugin.zip my-plugin`（zip 根目录是包目录或直接是包内容都可以）。

## 3. 清单（manifest.json）字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `format` | 是 | 固定 `1` |
| `type` | 是 | `plugin`（主题包是 `theme`，本文不讲） |
| `id` | 是 | 小写字母开头，字母、数字、连字符，2–40 位；zip 里的目录名必须等于它；不能与内置插件同名（`streaming-unlock`、`local-vault`），也不能以 `dstatus-` 开头（官方插件专用前缀，用了会被拒绝安装） |
| `name` / `description` | 是 | 插件卡片的标题与一句说明 |
| `version` | 是 | 三段语义版本，如 `1.2.0`、`1.3.0-beta.1`；升级只接受更高版本，相同版本视为重装 |
| `protocol` | 是 | 固定 `2` |
| `main` | 否 | 后端入口文件（CommonJS）；省略就是纯页面插件 |
| `defaults.fresh` / `defaults.upgrade` | 是 | 新装、升级后插件开关的默认值（布尔）：「开启」= 插件运行（`start` 被调、定时器会跑）；站长之后手动开关的记录优先 |
| `permissions` | 否 | 用到的能力清单，见第 4 节；没声明就不能用 |
| `outboundPurposes` | 否 | 出站地址按用途分组，只影响批准页的显示：`[{ "purpose": "域名注册局：只查询到期日", "hosts": ["rdap.verisign.com", ...] }]`。每个 host 必须是已声明的 `net:outbound:<host>`、只能出现在一组里；批准页把同一组合成一行「访问外网：<用途>（N 个地址）」。授权本身不变，站长仍是一次批准全部 |
| `engines.dstatus` | 否 | 要求的主控版本范围，如 `">=2.27.0"`（填你开发时主控的版本：看前台页面最底部的版本号；站长在「个性化」里关掉了版本显示时看不到，可以临时打开）；只支持 `>= > <= < =` 与裸版本、`*`，不支持 `^ ~ \|\|`；不确定就省略。与 `protocol` 无关：`protocol` 固定 2，`engines` 只管主控版本 |
| `dataVersion` | 否 | 你自己数据结构的版本（正整数，缺省 1），改了结构就 +1 并提供 `migrate`（第 9 节）。只有「已保存的数据版本 ≠ 新包的 dataVersion」时才会调 `migrate`；两边都缺省 1 就永远不调 |
| `contributes.pages` | 否 | 后台页面，见第 6 节 |
| `contributes.tools` | 否 | AI / MCP 工具，见第 7 节 |
| `contributes.notificationEvents` | 否 | 通知事件 `[{ key, title, desc? }]`；`key` 只能用字母和数字（推荐小驼峰，如 `nodeExpiring`），在插件内唯一。见第 4 节 notify |
| `ui.settingsSchema` | 否 | 设置表单结构文件路径（相对包根，如 `settings.schema.json`；JSON Schema 子集），主控自动生成设置表单，见第 8 节 |
| `ui.assets` | 否 | 页面静态文件目录，缺省 `ui`；可以有子目录，页面入口与引用的文件都必须在这个目录内 |
| `ui.web` | 否 | 访客页区块（首页节点卡、节点详情里的插件区块）。协议已定义但主控尚未开放：现在写了会被拒绝安装（`PLUGIN_PACKAGE_UNSUPPORTED`），先别写 |
| `data.onUninstall` | 否 | 卸载时自己的数据怎么处理的缺省：`keep`（缺省，重装后还在）或 `delete`；站长卸载时可以改 |
| `data.retentionDays` | 否 | 存储记录保留天数（按每条记录的最后更新时间，主控每 6 小时清一次），缺省永久。你自己按业务删旧记录与它互不干扰，可以同时用：它只是保底 |
| `resources.memoryMb` | 否 | 申请的内存上限（16–256，缺省 64）；主控内存紧张时可能拒绝开启。Buffer、大字符串这类堆外内存另有上限 `max(64 MB, 2 × memoryMb)`，超了插件会被停；同步代码连续 60 秒不让出也会被停，长计算请分批（每批之间 `await` 或交给定时器） |
| `resources.storageMb` | 否 | 存储配额（缺省 8，上限 64）|
| `author` / `homepage` / `license` | 否 | 展示用 |
| `group` / `icon` | 否 | 插件页分组名（随便起，如「示例」「报表」；同名就并进同一组，和官方插件的分组互不影响）；图标用主控图标表里的语义键（常用：`extension` 扩展、`world-www` 网络、`bell` 通知、`clock` 定时、`database` 数据；完整表见 `docs/图标清单.md`），不认识的键回落为 `extension`，不会拒绝安装。页面的 `icon` 用同一张表 |
| `details.settings` / `details.whenDisabled` | 否 | 插件卡片抽屉里的说明条目：`[{ title, desc, href?, label? }]` / `[{ title, desc }]` |

依赖：插件自带全部依赖（推荐 esbuild 打成单文件；也可随包带 `node_modules`）。主控不会 `npm install`，插件也 require 不到主控的依赖；不接受原生扩展；只支持 CommonJS。只能 require Node 内置模块与本插件目录里的文件。

## 4. 能力（ctx）与权限

> 插件代码跑在主控旁边的独立进程里的一个 Worker 中，能用的 Node 内置模块只有纯计算类（`path`、`url`、`util`、`events`、`buffer`、`crypto`、`stream`、`string_decoder`、`zlib`、`querystring`、`assert`、`timers`、`os` 等）。`fs`、`child_process`、`http`/`https`、`net`（只剩 `isIP`、`BlockList` 这类判断函数）、`dns`、`worker_threads`、`vm` 以及全局 `fetch` 都用不了，`require` 时会收到 `PLUGIN_CAPABILITY_DENIED` 并提示该用哪个 `ctx` 能力；只能引用自己包里的文件（含自带的 `node_modules`）。有副作用的事全部经 `ctx`。


所有方法都是异步的；参数与返回值必须可 JSON 序列化；错误以带 `code`、`message` 的 Error 抛出。

| 权限 | ctx 能力 | 说明 |
|---|---|---|
| 不需声明 | `ctx.log.debug/info/warn/error(message, meta?)` | 写进主控日志（来源 `plugin:<id>`，后台「日志管理」按来源搜），有限速（每分钟 120 条、单条 2000 字），只用于排障 |
| 不需声明 | `ctx.settings.get()` / `getWithRevision()` / `set(value, { expectedRevision? })` / `onChange(fn)` | 插件自己的设置对象（整份替换，≤ 64 KB）。从没保存过时 `get()` 返回 `{}`——schema 里的 `default` 只用于表单预填，不会自动写进设置，代码里要自己兜底；`required` 也只约束表单与写入校验，不会凭空生成值。无论是站长在表单保存还是你用 `set()` 写，主控都先按 schema 校验，不合法的直接拒绝（`PLUGIN_SETTINGS_INVALID`），所以 `onChange` 收到的值一定合法，不用再校验一遍。带 `expectedRevision` 可防并发覆盖（冲突报 `PLUGIN_SETTINGS_CONFLICT`）；管理员在插件页改了设置会触发 `onChange(settings)` |
| `timers` | `ctx.timers.every(name, intervalMs, handler)` / `clear(name)` | 只有固定间隔，没有 cron 和一次性定时。**要做「每天几点」**：开一个 60 秒的定时器，每次比对当前时刻与设置的 HH:MM，用存储记下「今天已做」防重复（主控错过时刻后下次醒来补做）。**按主控的业务时区算**：`(await ctx.host.capabilities()).host.timezone` 给出 `{ label: "UTC+8", offsetMinutes: 480 }`（面板统一用的时间，与运行机器的时区无关），用 `Date.now() + offsetMinutes * 60000` 再取 UTC 的年月日时分即可。间隔 ≥ 1 秒，每插件最多 8 个；第一次在一个间隔之后触发（启动就要跑一次的话在 `start` 里自己调一次）；上一轮没跑完这一轮跳过；handler 抛错只记日志，不会让插件进失败态；插件关闭时宿主清掉 |
| `storage` | `ctx.storage.collection(name)` → `get(key)`、`insert(key, value, { sid? })`、`put(key, value, { sid? })`、`update(key, value, { expectedVersion, sid? })`、`delete(key, { expectedVersion? })`、`list({ prefix?, sid?, limit ≤ 200, cursor? })` → `{ items, next }`（按 key 升序；第一页不传 `cursor`；`next` 为 `null` 表示没有下一页，否则原样传回去取下一页；`limit` 缺省 50）、`count({ prefix?, sid? })` | 键值存储，每条 ≤ 256 KiB，总量受配额；collection 与 key 是 1–120 字的 `A-Za-z0-9._:-`。`get` 返回 `{ key, value, version, sid, updatedAt }`，不存在返回 `null`；`insert` 已存在即失败（`PLUGIN_STORAGE_EXISTS`，可当唯一约束用）；`put` 有则覆盖；`update` 要带读到的 `version`，被别人改过报 `PLUGIN_STORAGE_CONFLICT`；`delete` 不存在不报错，返回 `{ deleted: false }`；记录带 `sid` 时节点删除会连带删掉（与插件是否运行无关）；`list` 按 key 排序返回 `{ items: [{ key, value, version, sid, updatedAt }], next }`，`next` 为 `null` 表示没有下一页 |
| `secrets` | `ctx.secrets.set(name, value)` / `get(name)` / `status(name)` / `delete(name)` | 加密保存 Token 之类的秘密（≤ 4 KiB，每插件 ≤ 32 个）；`status` 只给 `{ configured, last4 }`。页面、日志、工具里永远只显示末 4 位 |
| `nodes:read` | `ctx.nodes.list({ page = 1, limit ≤ 100 })` → `{ items, total, page, limit }`；`ctx.nodes.get(sid)`（不存在返回 `null`）；`onRemoved(fn)` / `onUpdated(fn)` | 节点只读视图 `{ sid, name, group: { id, name }, tags, online, publicIp: { ipv4, ipv6, updatedAt, stale } \| null, expireAt }`（`expireAt` 是到期时间毫秒时间戳，没设到期为 `null`；`publicIp` 没上报为 `null`），不含上报原文与任何凭据。翻页：`page` 从 1 递增，直到拿到的 `items` 少于 `limit`。同一时刻只能有一个列表请求在途。事件带 `{ sid }`（`onUpdated` 只在名称/分组/标签变化时发，上线下线不发），可能丢失，关键状态靠查询 |
| `metrics:read` | `ctx.metrics.traffic({ sids?, page, limit ≤ 100 })` → 每台的 `usedBytes`、`limitBytes`、`ratioPercent`（封顶 100，超额用 `usedBytes / limitBytes` 自己算）、`periodStartAt` / `periodEndAt`（毫秒）、`completeness`（complete / partial / unavailable）；`ctx.metrics.uptime({ from, to })`（毫秒，跨度 ≤ 31 天）→ `state`、`totals.availability`（0–1）与每台的在线 / 掉线 / 未知秒数、`outageCount`、`ongoing` | 读全部节点的流量用量与历史在线统计（与首页、后台时间线同一口径）；读不到的给 `null`，别当成 0。同一参数 60 秒内复用结果，每分钟重新统计最多 6 次 |
| `notify` | `ctx.notify(eventKey, title, text)` → `{ delivered, held, reason }`（`held` 为真表示免打扰期间已暂存、稍后发出，不算已送达；正文是纯文本，`\n` 分行与空行会原样保留；最终发到 Telegram / 邮件 / Webhook 的长度由各渠道自己截，建议正文 ≤ 2000 字、名单超过 50 条就写「等 N 个」；App 推送横幅标题是 `title`、正文只显示 `text` 前 160 字左右，所以最要紧的话写在前两行） | 事件必须先在 `contributes.notificationEvents: [{ key, title, desc? }]` 声明（没声明抛 `PLUGIN_NOTIFY_UNKNOWN`）；主控通知规则页会出现「插件：<名称>」一组开关，站长决定发不发、发到哪。开发时想看通知长什么样、渠道通不通：在后台「通知管理 › 规则」对这条插件规则点「测试发送」，不用造真实数据。站长关掉了或没配渠道时不抛错，返回 `{ delivered: false, reason }`；你的「已提醒」状态按自己的业务定，一般发出调用就算提醒过 |
| `http:admin` | `ctx.http.handle(async (req, { signal }) => ({ status, json }))` | 提供后台接口 `/api/plugins/<id>/<path>`：主控做管理员鉴权与 CSRF 后转给你 `{ method, path（以 / 开头）, query, body（≤ 1 MiB）, adminId, dryRun }`。`query` 里的值都是字符串（`?days=30` 拿到 `"30"`），自己 `Number()`。状态码建议：参数错 400、找不到 404、没配置凭据 409、上游失败 502、其他 500；`json` 里带 `errorCode` 与中文 `message`。`dryRun` 由调用方用查询 `?dryRun=1` 或请求体 `{ "dryRun": true }` 触发（页面里 `DStatusPlugin.api("POST", "/x", { query: { dryRun: 1 } })`）。15 秒超时（超时会触发 `signal`，别再继续写）。页面（第 6 节）与 App 都经它读写数据。响应形状由你定，建议 `{ success, data }` / `{ success: false, errorCode, message }` |
| `tools` | `ctx.tools.handle(name, async (args, { dryRun, signal }) => result)` | 提供 AI / MCP 工具，声明见第 7 节 |
| `net:outbound:<host>` | `ctx.net.fetch(url, { method?, headers?, body?, signal?, maxResponseBytes?, skipBodyOnError? })` → `{ status, headers, text, bodySkipped? }` | 出站请求，只许 https；目标解析到本机或内网时拒绝（`PLUGIN_NET_BLOCKED`）；只放行声明过的主机（可通配 `*.example.com`，一个主机一条权限；多了用 `outboundPurposes` 分组，见第 3 节）；不跟随重定向，30 秒超时，响应体 ≤ 512 KiB，大结果请分页。`maxResponseBytes` 只能调低读取上限，超出报 `PLUGIN_NET_TOO_LARGE`（不返回截断内容）；`skipBodyOnError: true` 时遇到非 2xx 不等正文、立即返回 `text: ""` 与 `bodySkipped: true`——有的服务回了错误状态却不结束响应（如 .com 注册局查未注册的域名），不加这个只能等满超时 |
| `pages` | （无 ctx 方法） | 声明了 `contributes.pages` 就必须申请它 |

高风险权限：`secrets`、`http:admin`、`pages`、`net:outbound:*`，以及每个 write 类工具。含高风险项的插件装好后处于「待批准」，管理员在插件卡片里看一眼申请清单、点「批准这组能力」才会运行；升级后权限集合一变，旧批准失效，要重新批准。所以：**只申请真正用到的能力**，申请越多越难被批准。

`ctx.host.capabilities()` 返回 `{ protocols: [2], methods: ["log", "settings.get", ...], host: { version, timezone: { label, offsetMinutes } } }`：`methods` 探测宿主有哪些方法（探测不了数据字段），`host.version` 是主控版本，`host.timezone` 是业务时区（见 timers）。节点视图没有「已暂停 / 已禁用」字段：`nodes.list` 返回站长添加的全部节点，被停用的也在其中（它们的 `online` 为 `false`，和掉线的分不开）；需要区分就让站长用分组或标签约定，不要自己猜字段名。

## 5. 生命周期

- `start(ctx)`：开启、主控启动、升级后都会调；在这里登记工具、接口、定时器、事件，做初始化。15 秒内要返回，超时算失败（插件页写明原因）；耗时的首轮工作可以不 `await`，`start` 返回后插件照常运行。未捕获的 Promise 拒绝会让插件进失败态，异步工作自己 `catch`。
- `stop(ctx, { reason })`：关闭（`disabled`）、主控关停（`shutdown`）、升级（`upgrade`）、失败后重试（`retry`）时调；只在 `reason === "disabled"` 时做「用户主动关闭」的收尾。宿主随后清掉你的定时器。
- 关闭 ≠ 删除：设置、存储、密钥都保留，重新开启即恢复；卸载按 `data.onUninstall` 处理。
- 崩溃：`start` 抛错、运行中未捕获异常、超内存 → 该插件进入失败态并写明原因；主控与其他插件不受影响。

## 6. 后台页面

清单里声明：

```json
"permissions": ["pages", "http:admin"],
"contributes": {
  "pages": [{ "id": "main", "title": "我的插件", "entry": "ui/index.html", "icon": "extension", "menu": { "group": "tools" } }]
}
```

- 每个页面生成地址 `/admin/plugins/<id>/pages/<pageId>`（`pageId` 为小写字母开头的字母数字连字符）。**页面默认不进菜单**，站长从插件页卡片或已安装列表的「打开」进入，也可在「个性化 › 后台菜单」加入、隐藏和排序；插件关闭时入口暂不显示，重新启用恢复选择与顺序。
- `menu` 只决定站长加入页面时的默认落位：第三方页面一律进侧栏「插件」分组（一个插件至多占一个顶级项，多页用插件名作父入口），`menu.group` 不生效。官方插件可把 `menu.group` 写为顶级菜单项 id（如 `servers`、`monitor`），页面作其子项，`after` 填同父项下某个子项 id（如 `servers-list`、`groups`），不填或无匹配则放末尾；写分组 id `core` / `system` / `tools` 则作该组顶级项；省略时进「插件」分组。`menu: false` 保持不提供菜单入口，只从插件页打开。
- 页面是普通 HTML，放在 `ui/` 里，在一个隔离框（不透明源 iframe）里运行：拿不到主控登录态，也不能自己发网络请求，**所有数据都经桥调用本插件的后台接口**。`ui/` 里不要放任何数据与秘密（无需登录即可下载）。
- 引入 SDK 与设计套件，就有和后台一致的外观与亮暗主题：

```html
<link rel="stylesheet" href="/plugin-ui-sdk/v1/kit.css">
<script src="/plugin-ui-sdk/v1/dstatus-plugin-ui.js"></script>
<script>
  DStatusPlugin.ready().then(async () => {
    const r = await DStatusPlugin.api("GET", "/items");          // → 本插件接口 /api/plugins/<id>/items
    if (r.status === 200) render(r.json);
  });
</script>
```

SDK（`window.DStatusPlugin`）：`ready()` 等桥就绪并拿到主题；`api(method, path, { query?, body? })` → `{ status, json }`；`toast(text, tone)`（`info` / `success` / `warning` / `error`）；`confirm({ title, content, confirmText, danger })` → 布尔；`navigate(href)`（只许站内地址）；`resize(height?)`；`theme()` / `onTheme(fn)`。高度自动跟随内容，不出内滚动条。TypeScript 声明：`/plugin-ui-sdk/v1/dstatus-plugin-ui.d.ts`。

设计套件（`kit.css`）类名以 `ds-` 开头，修饰符用双连字符（`ds-btn ds-btn--primary`）。常用写法：

```html
<div class="ds-page">
  <section class="ds-card">
    <h2 class="ds-card__title">标题</h2>
    <p class="ds-card__desc">一句说明</p>
    <div class="ds-row">
      <button class="ds-btn ds-btn--primary">主要</button>
      <button class="ds-btn ds-btn--sm">小按钮</button>
      <button class="ds-btn ds-btn--danger">危险</button>
      <span class="ds-badge ds-badge--success">正常</span>
      <span class="ds-badge ds-badge--warning">注意</span>
    </div>
    <div class="ds-field"><label class="ds-label">名称</label><input class="ds-input"><p class="ds-help">帮助文字</p></div>
    <div class="ds-alert ds-alert--info">提示条</div>
    <table class="ds-table"><thead><tr><th>列</th></tr></thead><tbody><tr><td class="ds-mono">等宽</td></tr><tr class="ds-table__empty"><td>暂无数据</td></tr></tbody></table>
    <div class="ds-tabs"><button class="ds-tab" aria-selected="true">全部<span class="ds-tab__count">3</span></button></div>
  </section>

```

其余：`ds-select` / `ds-textarea` / `ds-checkbox`、`ds-stack`（纵向间距）、`ds-muted` / `ds-small`、`ds-modal`（`ds-modal__panel` / `__head` / `__title` / `__subtitle` / `__body` / `__foot`，加 `hidden` 隐藏）、`ds-menu`（`ds-menu__list` / `ds-menu__item`）、`ds-pagination`、`ds-dot`（`--online` / `--warning`）、`ds-progress` / `ds-progress__bar`、`ds-table-wrap`（表格外层，窄屏横向滚动）；`ds-badge` 与 `ds-alert` 都有 `--success / --warning / --error / --info` 四种。颜色全部来自主控主题，不要写死色值。想看页面长什么样，用开发者模式装进你自己的主控看（第 10 节），没有离线预览。

## 7. AI / MCP 工具

清单里声明（JSON Schema 子集，工具入参与第 8 节设置表单通用：`type` 为 `string / number / integer / boolean / array / object`；通用关键字 `title`、`description`、`default`、`enum`、`const`、`nullable`；字符串 `minLength/maxLength`、`pattern`、`format`（`uri`、`email`、`hostname`、`date-time`、`ipv4`、`ipv6`）；数字 `minimum/maximum`；数组 `items`、`minItems/maxItems`、`uniqueItems`；对象 `properties`、`required`、`additionalProperties`；嵌套最多 6 层；写了不支持的关键字安装即拒绝）：

```json
"permissions": ["tools"],
"contributes": {
  "tools": [
    { "name": "myplugin_offline_count", "title": "统计离线节点", "category": "read",
      "description": "返回离线节点数量与名单", "inputSchema": { "type": "object", "properties": {}, "additionalProperties": false } },
    { "name": "myplugin_note_add", "title": "记一条备注", "category": "write", "dryRun": true,
      "description": "给节点加一条备注；dryRun 只预览",
      "inputSchema": { "type": "object", "properties": { "sid": { "type": "string", "title": "节点" }, "text": { "type": "string", "title": "备注", "maxLength": 200 } }, "required": ["sid", "text"], "additionalProperties": false } }
  ]
}
```

- `name` 小写字母开头的字母数字下划线、全局唯一，建议带插件前缀；`category: "write"` 的工具算高风险、需要批准。规则：真写一律要站长在入口确认，带 `dryRun: true` 的调用不用确认；面板 AI 一般先 dryRun 拿预览再请求确认，所以 dryRun 的返回要把「将要发生什么」写清楚，站长看的就是它。MCP 客户端由对方自己决定要不要先 dryRun。
- 入参由主控按 schema 校验后才到你的处理函数；schema 里的 `default` 只是给 AI 看的提示，缺省值不会自动填进 `args`，代码里自己兜底；声明了 `dryRun: true` 的工具收到 `dryRun === true` 时只预览、不能有副作用；没声明的工具收到 dryRun 直接被拒。
- 返回值建议 `{ ok: true, ... }` 或 `{ ok: false, code, message }`，AI 与 MCP 客户端都能读懂（工具的错误字段叫 `code`，后台接口响应的错误字段叫 `errorCode`——前者给 AI 读，后者沿用主控接口的口径；主控都不强制，保持一致即可）。
- 插件开启时工具自动出现在主控的 MCP `tools/list`、全局 AI 与 Telegram AI 里；关闭即消失。
- 给人看的名字只写在清单里，主控不会替你起：工具的 `title` 是 AI 助手的步骤名、确认卡标题和 MCP 客户端里显示的名字；入参属性的 `title` 是确认卡明细的字段名（如「备注：xxx」），不写就显示属性名。`description` 只给 AI 看。

## 8. 设置表单

`ui.settingsSchema` 指向一个 JSON Schema 子集文件（顶层 `object`，属性用 `title` 作标签、`default` 作缺省），主控在插件卡片抽屉里自动生成表单；保存后 `ctx.settings.onChange` 收到新值。

```json
{ "type": "object",
  "properties": {
    "threshold": { "type": "integer", "title": "离线阈值", "minimum": 1, "maximum": 100, "default": 3 },
    "mode": { "type": "string", "title": "模式", "enum": ["quiet", "loud"], "default": "quiet" },
    "enabled": { "type": "boolean", "title": "启用提醒" }
  },
  "required": ["threshold"], "additionalProperties": false }
```

## 9. 升级、数据迁移与卸载

- 升级 = 装更高版本的 zip：主控先停旧版、快照你的设置与存储、换目录、启动新版；新版启动失败自动回退到旧版。
- 改了存储结构：`dataVersion` +1，并在入口导出 `migrate(ctx, { from, to })`，用 ctx 把旧结构改成新结构（限时 5 分钟，失败回退）。
- 卸载：停插件 → 按 `data.onUninstall` 处理存储与密钥 → 删目录。`keep` 时重装同 id 能沿用旧数据。注意 `data.onUninstall` 只是缺省：站长卸载时可以改成保留或一并删除；插件关闭时站长也能在插件卡片里清空你的存储与密钥（设置保留）。所以别假设数据一定还在——`start` 时把「什么都没有」当成正常情况处理。

## 10. 在自己主控上自测

站长平时只能从官方插件市场（以及随主控附带的官方包）安装插件。你自己开发的插件，在自己的主控上用「开发者模式」装进去自测。需要一台你自己的 DStatus 主控（免费版即可）。

1. 后台「插件」页右上角打开「开发者模式」。打开时要再验证一次管理员身份；开着期间插件页顶部一直有提示。
2. 点提示里的「安装开发包」：填主控机器上的插件目录（代码就在主控那台机器上时最方便，Docker 部署就把目录挂进容器再填容器里的路径），或上传 zip。
3. 申请了高风险权限（第 4 节）的插件装好后是「待批准」：在插件卡片里看一眼申请清单，点批准才会运行。
4. 装好的插件标「开发中·未审核」，和正式插件一样运行：页面、接口、定时、通知、设置都能用；AI 助手与 MCP 里你的工具名字后面带「（开发中）」。
5. 改完代码：从目录装的会自动热更新——保存后约 1 秒主控按原目录重新安装（版本号没变就是重装，改了就是升级）；新代码启动失败自动退回上一版；清单新增了权限不会自动生效，要在卡片上点「重新加载」确认。每次结果写在插件目录的 `.dstatus/last-reload.json`（`result` 为 `running` / `pending-approval` / `permissions-changed` / `failed`，失败时 `message` 是原因），打包上架时会自动跳过这个目录。页面文件改了刷新浏览器即可。监听在少数环境（如某些网络盘、挂载方式）可能不触发，这时点卡片上的「重新加载」；上传 zip 装的不热更新，重新上传一次。
6. 看日志与报错：`ctx.log` 写的内容在后台「日志管理」里按来源 `plugin:<你的 id>` 搜；启动失败、超时、权限不够的原因写在插件卡片上。
7. 关掉开发者模式：所有开发中的插件立即停止，开不了；数据与设置都保留，再打开就按原来的开关恢复。AI 助手与 MCP 能帮你关掉开发者模式，但不能打开。

限制：开发包只收插件（主题不行）；`id` 不能用 `dstatus-` 前缀；同一个 `id` 已经装了官方版本的，先卸载官方版本再装开发包。

自测通过后按 `docs/投稿.md` 投稿；我们按 `docs/审核标准.md` 审核，通过后由官方打包签名、收进插件市场，其他站长才能安装。

## 11. 交付前自查

- 对照 `docs/审核标准.md` 逐条过一遍。
- 清单只申请用到的权限；工具名带前缀；页面里没有数据与秘密。
- 关闭插件后：没有定时器、没有出站请求、页面与工具消失；重新开启后数据还在。
- 出错时让站长看得懂：接口返回明确的 `errorCode` 与中文说明；日志只写排障信息，不写秘密。
- 手机宽度看一眼页面不溢出（设计套件已处理大部分）。

## 12. 常见错误

| 现象 | 原因 |
|---|---|
| 安装即拒绝「不认识的贡献点 / 不支持关键字」 | 清单字段或 schema 用了本文没有的东西 |
| 「目录名与清单 id 不一致」 | zip 里的目录名要等于 `id` |
| `PLUGIN_OFFICIAL_ID` | `id` 用了 `dstatus-` 前缀，这是官方插件专用的；换一个前缀 |
| `PLUGIN_DEV_MODE_OFF` | 开发者模式关着：开发中的插件不能装、不能运行；到插件页打开开发者模式 |
| 装好后一直「待批准」 | 申请了高风险权限，到插件卡片里批准 |
| `PLUGIN_PERMISSION_DENIED` | 用了没在 `permissions` 里声明的能力 |
| `MODULE_NOT_FOUND` | 插件 require 了主控的依赖；把依赖打进包里 |
| 工具「不支持 dryRun」 | 声明里加 `"dryRun": true` 并在处理函数里尊重它 |
| 页面空白 | 看浏览器控制台；页面里不能直接 fetch，要用 `DStatusPlugin.api` |
| 每天定时跑在错的时刻 | 按 `capabilities().host.timezone`（UTC+8）算，不要用运行机器或浏览器的时区 |
| `?days=30` 比较出错 | `query` 的值是字符串，先 `Number()` |
| `onChange` 收到不合法的设置 | 不会发生：主控按 schema 校验后才保存；收到了就是 schema 本身没限制 |
