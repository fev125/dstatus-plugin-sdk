# 投稿与更新

插件要收进官方插件市场，其他站长才能安装。投稿就是把插件源码和一份投稿单交给官方：在 GitHub 上发 Pull Request；或者官方给你的是本地目录时，直接在目录里用 git 提交。审核结果写回投稿单。

## 投稿前

- 插件已在你自己的主控上用开发者模式装上并跑通（`开发指南.md` 第 10 节），开关过一次，日志里没有报错。
- 对照 `审核标准.md` 逐条自查。
- 插件目录里有 `README.md`（写法看 `template/README.md`）。

## 投稿

1. 插件源码放在 `plugins/<id>/`，提交：`git add plugins/<id> && git commit -m "<id> <version>"`。只提交你的插件目录，不要改资料包自己的文件。
2. 复制 `submissions/投稿单模板.md` 为 `submissions/<id>-<version>.md`，逐项填好；「提交」一栏填第 1 步的提交号（`git rev-parse HEAD`）。
3. 提交投稿单：`git add submissions/<id>-<version>.md && git commit -m "投稿 <id> <version>"`。
4. 在 GitHub 上：fork 官方资料仓库（https://github.com/fev125/dstatus-plugin-sdk ），把这两次提交推到你的 fork，向官方仓库发 Pull Request，标题写「投稿 <id> <version>」。审核结论回复在 Pull Request 里，同时写回投稿单。本地目录投稿时跳过这一步。
5. 投稿单末尾「审核结果」的状态保持「待审核」，等审核方写回结论。

审核与打包都按投稿单里的那个提交：投稿后再改的代码不算数。要改就升版本号重新投稿。

## 审核结果

- **通过**：官方按你提交的源码原样打包、签名，收进官方插件市场。站长在后台「插件 › 插件市场」能看到，标「社区·已审核」。
- **需修改**：逐条写明问题和位置。改完升版本号，重新投稿。
- **不通过**：写明原因。

## 更新

新版本同样投稿：`version` 递增，投稿单填「变更说明」。新增权限、新增出站目标、数据结构变化（`dataVersion`）要单独写清楚。站长升级时，新增的高风险权限要重新批准。

## 撤回

上架后发现安全问题（例如把数据发到说明以外的地方、隐藏功能），官方会撤回该版本：已装这个版本的主控会停用它并通知站长，站长的数据保留。修好后升版本号重新投稿，审核通过上架后站长可以直接更新。
